title: Coding sessions
---

A coding session takes one work item from plan to merged change, read from top to bottom.

### What you do here
- Follow the steps: Plan, Changes, Tests, Pull request, Review, Done. The current step is open.
- Use the one highlighted button for the next action.
- Record the review: approved, needs changes or rejected, for the whole plan version.
- Find counters and ids under Details.

### Next steps
- [Open work items](/chat?area=work&work_view=board)
- [Review plans](/chat?area=work&work_view=changePlans)
- [Set up the workflow](/chat?area=workflows&tab=workflowList)

### Good to know
- A step is done only by recorded evidence: a planned check is not a passed test.
- A review does not approve the plan, start an agent or approve a pull-request commit.
- Restart from scratch is in ⋯; the declined result stays.
